独立复审按 SQL 完整 upstream request 匹配 debug 中的 v1internal request，再用真实 trace 找 upstream response；27/27 各对应一份 request / response，capture 未截断。解码原 raw stream 的 `response.usageMetadata` 后，与客户端回执的完整 usageMetadata 字典逐条相同，差异 0。以下数值据此使用实际最终上游回执，不使用容量估数、缩放值或重算 total。

A 首条实际 input=39,775、candidate=14、total=39,789，cache/thought 字段缺席；空资料补测 input=39,592、candidate=81、total=39,673，也没有 cache/thought。缺失不是 0。其余 25 条有实际 cache；27 条均没有 thoughtsTokenCount，不由 total 相减补造思考数。

重复 body 与同时间戳不会按 UUID 猜关联。公开结果采用隔离串行完整 JSON 与独立 trace 核验；无法唯一关联时保留未知。新网关 15 条实际派发记录均为 1；旧网关 12 条没有该字段。debug 中单个 attempt0 / 最终回执不能证明旧 endpoint fallback 总次数，因此旧 physical coverage 仍为 0/12，实际账单未知。
